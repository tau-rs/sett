Every arch screen is built from what is on this page: one tokens file (CSS variables, light and dark, mirrored as plain values in arch-tokens.json for the canvas), eleven components with all their states, five rules, and two screens rebuilt from the components to prove they cover the reference pages. The shell, the map anatomy and the frame are fixed by the product spec; this page styles them, it does not redesign them.

tokens arch-tokens.css · arch-tokens.json

Two surfaces, two palettes. The chrome (panes, chips, cards) is cool grey on white; the map is warm paper with warm-grey items so it reads as the document at the centre and never competes with the chrome around it. Semantic colours are used as fills and text; session colours are used as outlines, dots and borders, so the two sets can coexist at 12 px.

rules encoded, not just written

verbslive in a pane's fixed bar (.verbs) or in a chip. There is no .modal class in the system; the update dialog and the ⌘P palette are the two popovers, and both are dismissed by Esc without a trace.
blockedis a .pill wherever its subject is named: in the selector, in a menu row, under the gated button, in a session-card row. Same pill, same words (asks · 2, collision, paused).
manual firstin every pair the manual door comes first and is the bold one: fix myself · with Yokohama, Update myself · with Yokohama, Resolve myself · with Yokohama. The split button is the one exception, and the "me first" setting swaps it.
textchips and cards separate with ·; labels are lowercase; identifiers, branch names, counts and file:line are mono. No uppercase eyebrows anywhere (the mocks had some; see the changes below).
darkevery token has a dark value; components never hard-code a hex. The session palette is re-tuned for dark (higher lightness for the main and sub, dark tints for bg) so the 12 px test holds on both.
motiononly .frame.live, .frame.waiting and arch-item-pulse animate; prefers-reduced-motion stills them all. Nothing has a hover transition.
sizenothing on a screen exceeds 14 px; 14 is for pane headings only. Map labels are 10 px and do not scale; folding handles scale.

changes from the reference pages and why

  1. Chip radius 6 → 4. The mocks drew Actions chips at 6 px, the same as cards. The handoff's scale (3 items · 4 chips · 6 cards) gives chips their own step so a chip reads as a control and a card as a container; the tag inside a chip is 3.
  2. Uppercase eyebrows dropped. The mocks' section titles (h6 in menus, panes and Reach) were uppercase with letter-spacing. The rule "lowercase labels" now applies everywhere; they are 10.5 px mute, no tracking.
  3. Frame rotate 4 s → 6 s. The session mock ran the sweep at 4 s and 3.2 s in two places; the handoff says ~6 s. One duration, one token (--t-frame).
  4. Waiting frame is amber over a tint, not amber over a hard-coded #EAD9B0. The pulse now animates opacity of an amber layer over sugBg, so it works in dark mode and under reduced motion (still amber).
  5. Semantic colours get dark-tuned foregrounds. The mocks kept sel/ok/bad/sug identical in dark and only changed their backgrounds; on dark paper those fail contrast as text. Dark now lifts each (e.g. sel #1F5FA8 → #5B95E0). Same for the session palette.
  6. Map palette is now tokens. The mocks hard-coded the warm map greys (#F1EFE8, #888780, #B4B2A9, #5F5E5A, #2C2C2A) in SVG. They are now --map-* with dark values, and duplicated as plain values in arch-tokens.json so the WebGL layer reads the same numbers.
  7. Session card foot link right-aligned, glyph column fixed at 12 px. The mocks varied; the card now has one grid so rows align across sessions.
  8. Thread pane top border is the pane's identity. The mocks coloured agent messages by background (ykBg). Now agent messages are outlined (1 px, 3 px left) in the session colour, sub-agents in the sub shade, and only your messages have a filled background; this keeps the 12 px palette test readable when two sessions' threads sit side by side, and the pane header's top border says which one you are in.
  9. Six session colours added (teal, magenta, cyan, olive, sienna, plum) with an assignment order. Teal sits close to ok green and plum close to violet at 12 px; they are ranked last for that reason, and a session is always named beside its colour.
  10. Question block keeps its "later". The mocks showed it only in a note; it is part of the component now, so "answering resumes, later leaves it waiting" is visible in the block itself.
  11. Deviation card shows the three typologies as fixed labels before the generated option text, so the pattern (back on the plan · update the plan · not this change) is recognisable whatever the wording.
  12. Not changed: the shell grid (220 · 1fr · 330), the tab bar, the map anatomy, the glyph set, IBM Plex, the 4 px grid, the 14 px ceiling, the `·` separator.

Constraint check · plain CSS and DOM, no framework, no icon font (glyphs are Unicode; the toolbar uses six characters that a 20-glyph SVG set can replace); every colour is a variable; map values exist as numbers; dark mode from day one; 13" density (the two screens above are 1,280 px wide at 100%).
